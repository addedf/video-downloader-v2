## 抖音实现

粘贴主页或完整分享文本后请求作者发布列表；“继续提取更早媒体”使用返回游标。每批最多 5 页、每页 18 条，整体预算 30 秒、单页最多 15 秒。发生后续页错误时保留已有资源和可用游标。只在平台明确返回结束时显示完整，不将空响应或连续无新增当作已取全。

预览按稳定资源 ID 合并，重叠页刷新媒体 URL。主页保存快照没有 100 项截断；支持全部／视频／图片、全选和勾选、可用的实况视频。下载校验来源、作者、资源 ID 与 CDN；临时文件验证后原子改名，失败时保留成功文件和已登记的相册 URI。

新增抖音逻辑仅位于 dy/cli/，没有修改 vendor 核心。

### 已有登录信息的复用

APP 现有抖音登录兜底已经接入主页请求，无需另建认证方案：`DyLoginModule` 从应用内 WebView 收集 Cookie，使用 `CookieVault` 加密保存并调用 `refreshCookies`；冷启动时 `warmUp` 也会读取保存的 Cookie。Python 主页直链、分享短链展开后的主页和游标续页都进入 `_resolve_profile_response`，读取当前配置里的 Cookie 后创建 `DouyinAPIClient`，最终由 aiohttp 会话发送。

Cookie 清理仅验证名称格式，不按白名单删掉登录／设备字段。用户可以在“我的 → 登录抖音”完成登录，返回后重新解析主页。此前的 HTTP 200 空响应来自未登录测试，不能作为 APP 已登录路径不可用的结论；后续真实验收应优先复用这个已有登录会话。

## 抖音真实复验与方案核对

用户提供的 `https://v.douyin.com/NLAMHptDQc0/` 在 2026-10-04 22:02:59–22:03:01 的匿名复验中正确展开为作者主页，sec_uid 识别正确。作品列表接口返回 HTTP 200、响应体 0 字节，未取得媒体。它提示会话、签名或风控存在问题，不是服务端明确要求登录；尚不能保证登录后一定成功。

没有发现与小红书类似的分享访问参数丢失问题。当前接口和 sec_user_id/max_cursor/count 参数与主流项目一致；值得补验的是游客会话、请求头及 UA/查询参数的一致性。

- [f2 2026-10-03 代码](https://github.com/Johnserf-Seed/f2/blob/62f01b95c1afb772d8cde5a4235c700b016155e8/f2/apps/douyin/handler.py#L555-L600)明确处理游客仅返回第一页、后续无分页字段的情况，并提示更多作品使用登录 Cookie。因此免登录第一页与免登录全量必须分别验证。
- [f2 请求头实现](https://github.com/Johnserf-Seed/f2/blob/62f01b95c1afb772d8cde5a4235c700b016155e8/f2/apps/douyin/utils.py#L611-L662)包括 x-tt-argus 和从会话取得的 uifid，当前产品没有该层。
- [Douyin_TikTok_Download_API v5](https://github.com/Evil0ctal/Douyin_TikTok_Download_API/releases/tag/v5.0.0)有浏览器生成游客身份的路线；它仍依赖完整会话、指纹及签名，不能作为裸请求稳定取全的证据。

游客方案作为可选后续优化保留。下一项真实验收优先使用 APP 已有登录会话验证第一页、续页和保存；如果带登录会话仍失败，再核对请求头和签名。本轮没有接入新签名代码或读取个人浏览器 Cookie。
